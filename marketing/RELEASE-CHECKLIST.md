# IslamicLives — pre-publication and release checklist

Updated 2026-10-12. Status is based on repository documentation, not live deployment verification.

## Stop-ship claims
- [ ] Adopt and document an explicit open-source license **before** calling the project open source or inviting code reuse under particular terms. Review contributor permissions, upstream source and artwork rights.
- [ ] Confirm the community member's preferred name, pronouns, project role, biography, link and permission to credit publicly.
- [ ] Recheck profile count and the number of atlas chapters from main and CHANGELOG at announcement time.
- [ ] Confirm actual web deployment URL and production availability with maintainer; no inferred live URL.
- [ ] Complete native device, screen-reader, TestFlight, and Play testing before any public store release assertion.
- [ ] Ensure public privacy, support and corrections policies appropriate to distribution.
- [ ] Do not assert scholar review without named qualified review and scope.
- [ ] Confirm images, fonts, brand assets, and book extracts have appropriate distribution rights.
- [ ] Review religious and historical examples for direct source and editorial uncertainty.
- [ ] Obtain final approval from community lead, engineer and editorial reviewer.

## Repo-reveal minimum
- [x] Public GitHub repository confirmed.
- [x] README and contributing guide publicly present.
- [x] Preliminary marketing copy and campaign calendar committed.
- [ ] Owner signs off copy and platform selections.
- [ ] Confirm first contributor attribution.
- [ ] Capture genuine screenshots / demo footage from verified build.
- [ ] Publish copy with repository URL and honest status disclosures.

## Publication runbook
1. Choose launch scope: public repository reveal first; production app/store announcements later.
2. Validate claims against current repository and changelog.
3. Obtain community-member attribution consent and approved images.
4. Select approved campaign assets from CREATIVE-BRIEF.md.
5. Schedule the 14-day program in SOCIAL-CAMPAIGN.md after approval.
6. Publish ANNOUNCEMENTS.md variants and track link engagement.
7. Moderate corrections promptly and direct contributors to CONTRIBUTING.md.
8. Issue an honest retrospective summarizing sources improved, bugs fixed, and next work.

## Review responsibilities
Product maintainer: functionality/release.
Editorial reviewer: claims/citations.
Qualified scholar: only specific reviewed content and method.
Marketing lead: brand consistency, distribution, consent.
Legal/licensing owner: license, third-party rights, privacy.

## Post-announcement tracking template
Date (UTC) | channel | asset | approved by | post URL | engagements | repo visits (if available) | issues opened | PRs opened | verified corrections | notable feedback

Never manufacture metrics or imply that social reach constitutes scholarly validity.
