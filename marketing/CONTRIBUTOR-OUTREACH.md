# Contributor outreach and community activation

## Public call
**Help build a more careful way to explore Islamic history.**

IslamicLives is a growing public GitHub project from the ummah.build community. We welcome thoughtful contributions across source research, content correction, localization, accessible UI, web/Expo engineering, testing and editorial workflows.

Especially valuable are **specific, checkable improvements**: a correct surah and ayah range; a hadith report and edition context; an uncertainty note acknowledging disagreement; a broken source link; a reproducible mobile bug; or a semantic-labeling fix.

Read the project contribution rules before submitting changes: https://github.com/ummahbuild/IslamicLives/blob/main/CONTRIBUTING.md

## Role-specific invitations

### Qur'an and hadith researchers
Help audit source claims with exact surah/ayah ranges and hadith collection/report numbers. Keep hadith grading and edition/translator information visible; distinguish text from interpretation.

### Academic historians and librarians
Improve dating notes, provenance, disputed identifications and bibliography quality. Prefer primary texts and credible academic editions; do not convert illustrative geographic points into claims of precision.

### Qualified Islamic scholars
We welcome scoped, documented review. A review badge is only appropriate when the named qualified reviewer has confirmed the reviewed material, method and scope, and consented to the attribution.

### Web and mobile engineers
Contribute focused fixes to the web/Expo workspace, shared content pipeline, generated pages, accessibility and validation scripts. Use the tests and PR checklist in CONTRIBUTING.md.

### Accessibility researchers and testers
Help test keyboard flows, focus, reduced motion, readable non-WebGL fallbacks, VoiceOver and TalkBack, and real iPhone/Android builds.

### Designers and educators
Create accessible learning journeys, accurate captions, annotation affordances and lesson prompts. Avoid visual depictions of prophets and misleading exact-history iconography.

### Arabic speakers, translators and editors
Help with careful transliteration, naming variants and multilingual usability after establishing a consistent review workflow. Do not silently merge distinct theological or historiographic viewpoints.

## Good first contribution examples
- Fix a broken citation with a stable source and exact claim alignment.
- Add a clearly scoped uncertainty note without altering theological claims.
- Improve keyboard navigation or reduced motion handling.
- Add a reproducible failing test for atlas fallback behavior.
- Improve profile readability at 390px.
- Audit one translation, edition note or transliteration issue.

## Review and safety guardrails
Search for existing issues first; avoid duplicate requests. Never present AI-generated religious claims as authority. Do not promise merge, endorsement or attribution. Security reports should follow docs/SECURITY.md, not a public issue. Contributor permissions and license terms need explicit maintainer clarification.
